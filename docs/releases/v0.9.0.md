# Kubecrate v0.9.0 release notes

## Summary

This release moves the cert-manager platform service chart `cert-manager` from v1.17.4 to v1.18.6 in `platform-services/cert-manager/base/`. It is step 2 of the one-minor-at-a-time path to v1.21.3. The Vanilla composition paths and values are unchanged.

## Breaking change

No Kubecrate path or values change. The upstream upgrade notes for 1.17 to 1.18 (https://cert-manager.io/docs/releases/upgrading/upgrading-1.17-1.18/) list two changes:

- The default of `Certificate.Spec.PrivateKey.RotationPolicy` changes from `Never` to `Always`. Kubecrate's defaults are affected only through a consumer's Certificates: a Certificate that sets no `rotationPolicy` gets a new private key at its next renewal, not at the upgrade, and cainjector then updates the caBundle of each webhook that injects from that Certificate. Kubecrate creates no Certificate itself. A consumer sets `rotationPolicy: Never` on a Certificate that must keep its key.
- The default of `Certificate.Spec.RevisionHistoryLimit` changes from unset to `1`. Kubecrate's defaults are not affected because Kubecrate sets no Certificate. A consumer's Certificate that sets no `revisionHistoryLimit` keeps only its newest CertificateRequest, and older ones are pruned.

## Details

- The 6 CRDs (`certificates`, `certificaterequests`, `issuers` and `clusterissuers` in `cert-manager.io`; `challenges` and `orders` in `acme.cert-manager.io`) serve and store only `v1` in both v1.17.4 and v1.18.6.
- The CRDs are chart templates (`crds.enabled: true`) with `helm.sh/resource-policy: keep`.
- `helm-values.yaml` is unchanged.
- Nothing else in the repository changes.

## Upgrade guidance

1. Be on Kubecrate `v0.8.0` first. Upstream recommends upgrading one minor version at a time (https://cert-manager.io/docs/installation/upgrade/).
2. Update the consumer repository's Kubecrate source tag to `v0.9.0`.
3. Run the consumer repository's render validation.
4. Reconcile.
5. Verify the `cert-manager` `HelmRelease` is Ready on chart v1.18.6, every Certificate, Issuer and ClusterIssuer is Ready, and each Certificate's `status.revision` is unchanged.

## Rollback

Rollback by restoring the previous exact Kubecrate tag `v0.8.0` in the consumer repository. Helm re-renders the CRD templates on the downgrade (`helm.sh/resource-policy: keep` only stops their deletion). Both versions serve only `v1`, so no stored object changes.
