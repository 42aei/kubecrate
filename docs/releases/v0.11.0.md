# Kubecrate v0.11.0 release notes

## Summary

This release moves the cert-manager platform service chart `cert-manager` from v1.19.6 to v1.20.5 in `platform-services/cert-manager/base/`. It is step 4 of the one-minor-at-a-time path to v1.21.3. The Vanilla composition paths and values are unchanged.

## Breaking change

No Kubecrate path or values change. See the upstream upgrade notes for 1.19 to 1.20 (https://cert-manager.io/docs/releases/upgrading/upgrading-1.19-1.20/). Three upstream changes to note:

- The cert-manager containers run as UID 65532 and GID 65532 by default (previously UID 1000 and GID 0; upstream v1.20.0 release notes, https://github.com/cert-manager/cert-manager/releases/tag/v1.20.0). Kubecrate's defaults pick up the new IDs: `helm-values.yaml` sets no `securityContext`, so the image user applies and Kubecrate's pods move from UID 1000 / GID 0 to 65532 / 65532. Nothing Kubecrate ships depends on the old IDs. A consumer that sets its own `securityContext` (for example `runAsUser`, `runAsGroup` or `fsGroup`) or relies on the old IDs (for example file ownership on a mounted volume) checks that it still fits.
- The aggregated `cert-manager-edit` ClusterRole no longer grants `create` on Challenges or `create`, `patch` and `update` on Orders (upstream advisory GHSA-8rvj-mm4h-c258, listed upstream under v1.20.3). This already shipped in `v0.10.0` (chart v1.19.6), so this tag does not change it again. Kubecrate's defaults are not affected by this tag. A consumer whose users or tools create or change Challenges or Orders directly needs its own Role, as the `v0.10.0` notes say.
- The feature gate `DefaultPrivateKeyRotationPolicyAlways` moved from Beta to GA and can no longer be disabled (upstream v1.20.0 release notes, https://github.com/cert-manager/cert-manager/releases/tag/v1.20.0). Kubecrate sets no feature gates, so its defaults are not affected. A consumer that disabled this gate to keep the 1.18 `rotationPolicy: Never` default must remove the gate setting and set `rotationPolicy: Never` on each Certificate that needs it.

## Details

- The 6 CRDs (`certificates`, `certificaterequests`, `issuers` and `clusterissuers` in `cert-manager.io`; `challenges` and `orders` in `acme.cert-manager.io`) serve and store only `v1` in both v1.19.6 and v1.20.5. No version and no field is removed in v1.20.5.
- The v1.20.5 schemas add one field, the optional enum `zoneType` (`AzurePublicZone` or `AzurePrivateZone`) of the Azure DNS-01 solver: `spec.acme.solvers[].dns01.azureDNS.zoneType` in `issuers` and `clusterissuers`, and `spec.solver.dns01.azureDNS.zoneType` in `challenges`. The other CRDs (`certificates`, `certificaterequests`, `orders`) add no field. Description-only changes are ignored.
- The `v1` version of `certificates`, `certificaterequests`, `challenges` and `orders` adds `selectableFields` for `.spec.issuerRef.group`, `.spec.issuerRef.kind` and `.spec.issuerRef.name`. This is CRD metadata for field selectors, not part of a stored object.
- The CRDs are chart templates (`crds.enabled: true`) with `helm.sh/resource-policy: keep`.
- `helm-values.yaml` is unchanged.
- Nothing else in the repository changes.

## Upgrade guidance

1. Be on Kubecrate `v0.10.0` first. Upstream recommends upgrading one minor version at a time (https://cert-manager.io/docs/installation/upgrade/).
2. Update the consumer repository's Kubecrate source tag to `v0.11.0`.
3. Run the consumer repository's render validation.
4. Reconcile.
5. Verify the `cert-manager` `HelmRelease` is Ready on chart v1.20.5, every Certificate, Issuer and ClusterIssuer is Ready, and each Certificate's `status.revision` is unchanged.

## Rollback

Rollback by restoring the previous exact Kubecrate tag `v0.10.0` in the consumer repository. Helm re-renders the CRD templates on the downgrade (`helm.sh/resource-policy: keep` only stops their deletion). Both versions serve only `v1`, so no stored object changes its version. The v1.20.5 Issuer, ClusterIssuer and Challenge CRDs add the field `azureDNS.zoneType` (see Details). After a rollback to `v0.10.0` the API server prunes it from stored objects, so a consumer that set it loses it.
