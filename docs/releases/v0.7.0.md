# Kubecrate v0.7.0 release notes

## Summary

This release moves the External Secrets Operator platform service chart `external-secrets` from 2.7.0 to 2.15.0 in `platform-services/external-secrets-operator/base/`. The Vanilla composition paths and values are unchanged.

## Breaking change

No Kubecrate path or values change. The ESO release notes v2.8.0 to v2.15.0 list no breaking changes or upgrade steps. ExternalSecret, SecretStore, ClusterSecretStore and ClusterExternalSecret serve and store only `v1` in both 2.7.0 and 2.15.0. A consumer still on `v1beta1` objects must move to `v1` first.

## Details

- 2.7 is end-of-life since 2026-07-18 and 2.15 is tested against Kubernetes 1.37. See https://github.com/external-secrets/external-secrets/blob/main/docs/introduction/stability-support.md .
- The chart adds one new CRD, `gitlabdeploytokens.generators.external-secrets.io`.
- The CRD schema no longer defaults `conversionStrategy`, `decodingStrategy` and `metadataPolicy`. The controller applies the same defaults, so a GitOps apply drops those fields from existing ExternalSecrets once and triggers one refresh.
- Chart 2.11.0 must not be pinned: its `global.imageRegistry` change was reverted in 2.12.
- `helm-values.yaml` is unchanged because its keys (`installCRDs`, `webhook.create`, `certController.create`) keep their meaning in 2.15.0.
- Nothing else in the repository changes.

## Upgrade guidance

1. Update the consumer repository's Kubecrate source tag to `v0.7.0`.
2. Run the consumer repository's render validation.
3. Reconcile.
4. Verify the `external-secrets` `HelmRelease` is Ready on chart 2.15.0 and every ExternalSecret is SecretSynced after its next refresh (up to its `refreshInterval`).

## Rollback

Rollback by restoring the previous exact Kubecrate tag in the consumer repository. The CRDs ship under the chart's `templates/crds/`, so Helm (not Flux's `crds: CreateReplace`) downgrades them. 2.7.0 serves the same `v1` versions, and the `gitlabdeploytokens` CRD is removed with it.
