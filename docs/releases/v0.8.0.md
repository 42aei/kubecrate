# Kubecrate v0.8.0 release notes

## Summary

This release moves the cert-manager platform service chart `cert-manager` from v1.16.3 to v1.17.4 in `platform-services/cert-manager/base/`. It is step 1 of the one-minor-at-a-time path to v1.21.3. The Vanilla composition paths and values are unchanged.

## Breaking change

No Kubecrate path or values change. The upstream upgrade notes for 1.16 to 1.17 (https://cert-manager.io/docs/releases/upgrading/upgrading-1.16-1.17/) list three changes:

- CA and SelfSigned Issuers with RSA keys of 3072 or 4096 bits now sign with SHA-384 or SHA-512. Kubecrate's defaults are not affected because Kubecrate creates neither a CA nor a SelfSigned Issuer. A consumer with such an Issuer checks its relying parties.
- The controller's log format changes. Kubecrate's defaults are not affected because Kubecrate sets no log filter. A consumer with a log filter on the old format must check it.
- The `ValidateCAA` feature gate is deprecated. Kubecrate's defaults are not affected because Kubecrate sets no feature gate.

## Details

- The 6 CRDs (`certificates`, `certificaterequests`, `issuers` and `clusterissuers` in `cert-manager.io`; `challenges` and `orders` in `acme.cert-manager.io`) serve and store only `v1` in both v1.16.3 and v1.17.4.
- The CRDs are chart templates (`crds.enabled: true`) with `helm.sh/resource-policy: keep`.
- `helm-values.yaml` is unchanged.
- Nothing else in the repository changes.

## Upgrade guidance

1. Be on Kubecrate `v0.7.0` first. Upstream recommends upgrading one minor version at a time (https://cert-manager.io/docs/installation/upgrade/).
2. Update the consumer repository's Kubecrate source tag to `v0.8.0`.
3. Run the consumer repository's render validation.
4. Reconcile.
5. Verify the `cert-manager` `HelmRelease` is Ready on chart v1.17.4, every Certificate, Issuer and ClusterIssuer is Ready, and each Certificate's `status.revision` is unchanged.

## Rollback

Rollback by restoring the previous exact Kubecrate tag `v0.7.0` in the consumer repository. Helm re-renders the CRD templates on the downgrade (`helm.sh/resource-policy: keep` only stops their deletion). Both versions serve only `v1`, so no stored object changes.
