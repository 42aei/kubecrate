# Kubecrate v0.4.0 release notes

## Summary

This release simplifies the Vanilla composition by removing the copy/paste-only per-service binding directories under `compositions/vanilla/platform-services/<service>/`. The stable consumer entrypoint remains `compositions/vanilla/entrypoint/`.

## Breaking change

This is a breaking change for consumers that directly referenced any of these lower-level paths:

- `compositions/vanilla/platform-services/external-secrets-operator`
- `compositions/vanilla/platform-services/envoy-gateway`
- `compositions/vanilla/platform-services/cert-manager`
- `compositions/vanilla/platform-services/kyverno`

Those paths are removed. Reconcile the corresponding service base instead:

- `platform-services/external-secrets-operator/base`
- `platform-services/envoy-gateway/base`
- `platform-services/cert-manager/base`
- `platform-services/kyverno/base`

Consumers that only reconcile `compositions/vanilla/entrypoint/` do not need to change their Kubecrate path. They should still update the pinned Kubecrate tag through a reviewed consumer-repository change and validate the rendered composition before merge.

The consumer repository's Kubecrate `GitRepository` should be named `flux-system-sync`; the Vanilla entrypoint's nested Flux `Kustomization` objects use that source name.

## Details

- Helm values files now live beside each service base as `platform-services/<service>/base/helm-values.yaml`.
- Each service base now generates its own values `ConfigMap` with a stable name.
- The Vanilla entrypoint Flux `Kustomization` objects now point directly at the service bases.
- Repository validation now renders `platform-services/external-secrets-operator/base` and `compositions/vanilla/entrypoint` in addition to the other service bases.

## Upgrade guidance

1. Update the consumer repository's Kubecrate source tag to `v0.4.0`.
2. Ensure the consumer repository's Kubecrate source is `GitRepository/flux-system-sync`.
3. If the consumer reconciles only `compositions/vanilla/entrypoint/`, keep that path unchanged.
4. If the consumer reconciles a removed per-service path, replace it with the corresponding `platform-services/<service>/base` path above.
5. Run the consumer repository's render/static validation.
6. Reconcile in a safe target and verify the platform-service `HelmRelease` resources become Ready.

## Rollback

Rollback by restoring the previous exact Kubecrate tag in the consumer repository. Consumers that moved direct per-service references to the new base paths must restore the old paths when rolling back to `v0.3.0`.
