# Kubecrate v0.5.0 release notes

## Summary

This release adds the NetBird operator as an optional platform service at `platform-services/netbird-operator/base/`. The Vanilla composition is unchanged.

## Breaking change

None. Consumers on v0.4.0 can move to v0.5.0 without other changes.

## Details

- New optional platform-service base `platform-services/netbird-operator/base/`: namespace `core-netbird-operator`, an OCI `HelmRepository` for `oci://ghcr.io/netbirdio/helm-charts`, a `HelmRelease` for chart `netbird-operator` `0.9.0`, and a generated values `ConfigMap`.
- Nothing reconciles the new base until a consumer opts in. `compositions/vanilla/entrypoint/` does not include it.
- A consumer that opts in supplies Secret `netbird-mgmt-api-key` and overrides `cluster.name`. See [`../netbird-operator.md`](../netbird-operator.md) for the binding contract and the accepted limits.
- Repository validation now renders `platform-services/netbird-operator/base`.
- The end-to-end proof is the tenant-01 rollout, tracked in https://github.com/42aei/bedrock/issues/101 until that slice's evidence exists.

## Upgrade guidance

1. Update the consumer repository's Kubecrate source tag to `v0.5.0`.
2. Keep the Vanilla path unchanged.
3. To use the NetBird operator, add a Flux `Kustomization` for `./platform-services/netbird-operator/base` from `GitRepository/flux-system-sync`, deliver the Secret, and override `cluster.name` as described in [`../netbird-operator.md`](../netbird-operator.md).
4. Run the consumer repository's render/static validation.
5. Reconcile in a safe target and verify the platform-service `HelmRelease` resources become Ready.

## Rollback

Rollback by restoring the previous exact Kubecrate tag in the consumer repository. A consumer that opted in to the NetBird operator must first remove its reconciliation of the new base before rolling back to `v0.4.0`.
