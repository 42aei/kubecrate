# Kubecrate v0.6.0 release notes

## Summary

This release moves the Envoy Gateway platform service chart `gateway-helm` from v1.4.2 to v1.5.9 in `platform-services/envoy-gateway/base/`. The Vanilla composition paths and values are unchanged.

## Breaking change

No Kubecrate path or values change. Envoy Gateway v1.5.0 has upstream breaking changes:

- The gateway-namespace-mode fleet name changes.
- The `XDSNameSchemeV2` runtime flag exists, is off by default in v1.5, and affects EnvoyPatchPolicies and ExtensionManagers.
- Endpoints absent from service discovery are removed even when healthy active checks pass.
- The `watchable_subscribe_total` metric `runner` label value is `xds`.
- Access log service (ALS) uses http2.

Full list: https://github.com/envoyproxy/gateway/blob/v1.5.9/release-notes/v1.5.0.yaml . v1.5.1 to v1.5.9 list no further breaking changes. Consumers that use any of these must check them before bumping.

## Details

- The v1.5 bootstrap has no `wasm_cluster`, so Envoy proxies stop resolving the single-label name `envoy-gateway.`, which produced steady CoreDNS SERVFAIL answers. See https://github.com/42aei/kubecrate/issues/38 .
- The chart bundles Gateway API CRDs that stay at v1.3.0 experimental.
- `helm-values.yaml` is unchanged because every key it sets still exists in the v1.5.9 chart values.
- Nothing else in the repository changes.

## Upgrade guidance

1. Update the consumer repository's Kubecrate source tag to `v0.6.0`.
2. Check the v1.5.0 breaking changes above against the consumer's Envoy Gateway resources.
3. Run the consumer repository's render/static validation.
4. Reconcile in a safe target and verify the `envoy-gateway` `HelmRelease` becomes Ready on chart `v1.5.9` and the Envoy proxy pods are replaced and Running.

## Rollback

Rollback by restoring the previous exact Kubecrate tag in the consumer repository. Because the `HelmRelease` sets `crds: CreateReplace` (`platform-services/envoy-gateway/base/helm-release.yaml:24-27`), Flux then also replaces the Gateway API and Envoy Gateway CRDs with the v1.4.2 chart's versions. A consumer that started using fields added in v1.5 must remove them first.
